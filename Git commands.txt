Start a new Git repository for an existing code base
$ cd /path/to/my/codebase
$ git init      (1)
$ git add .     (2)
$ git commit    (3)
Create a /path/to/my/codebase/.git directory.

Add all existing files to the index.

Record the pristine state as the first commit in the history.

 From the documentation: Running git init in an existing repository is safe. It will not overwrite things that are already there. The primary reason for rerunning git init is to pick up newly added templates.
 
 
 Other commands - 
 - To modify message use git commit --amend 
 - to make changes to the commit, 
	* Adding more changes to the commit: If you've made a commit but then realize that you forgot to add a file or you've made an additional change that should be part of the commit, you can use the following workflow:
		Stage the additional changes with git add
		Then, use git commit --amend If you don't want to change the commit message, you can use git commit --amend --no-edit
		
Git statuses - 
Modified - New is also modified 
Untracked - not being tracked by git, i.e. git add is not run after changes to the file 
Staged - after git  add . is run 
Committed - Snapshot has been taken (including Staged files have been saved) after git commit -m "" / git comment --amend has been run
